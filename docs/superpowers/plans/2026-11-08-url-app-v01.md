# URL App V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将单文件 HTML 转为包含完整数据的 URL，在静态 Runtime 中校验、隔离运行。
**Architecture:** protocol、packager、runtime 三个 TypeScript 模块；Node CLI 和简洁网页共用打包接口；Vite 输出独立静态站点。
**Tech Stack:** TypeScript, Vite, Web Compression Streams, Web Crypto, parse5, Vitest, Playwright.
**Spec:** ../specs/2026-11-08-url-app-design.md（用户已要求基于此计划执行第一版）。

## Global Constraints
- 第一版协议：`#uapp=1&codec=gzip&size=<UTF-8 bytes>&sha256=<lowercase hex>&payload=<unpadded Base64URL>`。
- 8 KiB 分享预警、256 KiB URL 硬限制、补充 1 MiB 解压硬限制；声明大小同样作为流式上限。
- iframe 仅 `allow-scripts`，CSP 在所有用户内容之前，默认禁用网络资源、表单、弹窗、顶层跳转。
- 仅接受已内联 HTML；保留原始字节语义，不进行可能改变代码/空白意义的自动精简。Vite/React/Vue 自动内联、WASM、分卷不属 V0.1。
- 新建独立仓库 `D:/Program/ai-work/url-app`，无原有工作树可复用；不修改邻接项目。
- 公开部署需要用户自己的 GitHub 目标仓库；先完成可审阅的产物与工作流，再处理发布。

## Review Focus
- 非法/重复协议字段、非规范 Base64URL、Gzip 损坏、伪造 size/hash。
- 声明小体积但实际解压很大的 payload，以及旧异步任务覆盖新 hash。
- 不可信 HTML 在 CSP 前执行/发起请求，DOM/Storage 隔离与外部资源引用。
- CLI 不存在文件、无效 UTF-8、覆盖输出；网页修改内容后仍展示过期链接。
- GitHub Pages 子路径部署、空 hash、刷新、浏览器缺少解压能力。
